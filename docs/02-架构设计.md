## 2. 关键设计决策

### 决策一：Agent 循环放在侧边栏，不放在 Service Worker

MV3 的 Service Worker 空闲约 30 秒即被回收，长对话必然中断。

| 方案 | 问题 |
|---|---|
| 放 Service Worker | 30 秒空闲被回收，长任务中断 |
| 放 content script | 页面一导航就销毁；且拿不到 chrome.downloads 等权限 |
| **放侧边栏页面** ✅ | 侧边栏在页面导航时保持存活，且是扩展页面，拥有全部扩展 API 权限 |

代价：侧边栏关闭则对话中断。这与所有主流 AI 侧边栏的行为一致，可以接受。

### 决策二：工具执行集中在 Service Worker，UI 只负责交互

侧边栏页面调用工具时，通过 `chrome.runtime.sendMessage` 把请求交给 Service Worker 执行。
好处：

- 侧边栏关闭后，仍可通过 MCP 触发工具（能力独立于 UI 存活）
- 权限集中在一处，便于审计
- 错误处理统一

### 决策三：handlers 与 bridge 解耦

最初 `service-worker.js` 静态 import `bridge.js`，而 `bridge.js` 需要动态 import `service-worker.js`
以复用工具实现 —— 这形成了循环依赖，且 MV3 中 `import()` 在 Service Worker 里被规范明确禁止，
导致 MCP 工具调用永久超时（实测卡满 120 秒）。

最终结构：

```
service-worker.js ──import──> bridge.js
        │                        │
        └──import──> handlers.js <┘
```

`handlers.js` 是叶子模块，不依赖任何其他扩展模块，循环彻底消失。

### 决策四：样式改写采用「独立根 + 可撤销」模型

所有注入的 CSS 挂在 `<div id="nbc-style-root">` 下的独立 `<style>` 元素上，每条规则带 `data-nbc-name`：

```html
<div id="nbc-style-root">
  <style data-nbc-name="preset-dark">   … </style>
  <style data-nbc-name="custom-hide">   … </style>
</div>
```

带来三个好处：

1. **精确撤销** —— `style.remove(name)` 只删指定规则，不影响其他
2. **完整复位** —— `style.reset` 清空根节点，页面 100% 恢复原状
3. **可审计** —— 用户在 DevTools 里一眼看到扩展改了什么

`scope` 参数可以把规则限定在某个选择器内，避免污染全站。

### 决策五：正文抽取自带轻量实现，但预留替换位

没有直接打包 Readability/Defuddle（约 100KB+），理由：

- 扩展体积敏感
- 本地实现已满足「正文 + 大纲 + 元信息 + 表格」需求（实测有效）
- 需要更高保真时，可替换为 defuddle（MIT，与 Obsidian Web Clipper 同源）

抽取算法：候选块评分（文本长度 + 段落数 + 链接密度惩罚 + 语义类名加分 + 标签加权）→ 选最高分容器 →
清洗噪音节点 → DOM 遍历转 Markdown。

### 决策六：DOCX 手写，不引第三方库

`shared/docx.js` 手写 ZIP（STORE 模式 + CRC32 表）与 OOXML，共约 200 行。

取舍：牺牲表格/图片/复杂排版，换来**零依赖、零供应链风险**。
需要完整排版时用 companion + pandoc。

### 决策七：双传输模式（direct / relay）

见 `01-可行性评估.md` 第 2 节。核心判断：**浏览器直连的可行性因服务商而异**，
所以架构上不能把「直连」写死成唯一路径。

## 5. 工具清单（28 个）

| 分类 | 工具 |
|---|---|
| 读取 | `page.read` `page.links` `page.tables` `page.images` `page.interactive` `page.screenshot` `page.eval` |
| 交互 | `page.click` `page.fill` `page.scroll` `page.highlight` |

| 表格 | `table.docs` `table.download` |
| 媒体 | `media.list` `media.download` |
| 导出 | `doc.export` |
| 导航 | `tab.list` `tab.open` `tab.switch` `tab.close` `tab.reload` `nav.back` |

工具描述直接进入模型上下文，因此描述写的是「**什么时候该用、怎么用**」，
而不仅是「这是什么」—— 这是工具调用准确率的关键。

### 5.1 表格批量下载的实现要点

这类页面（报表/清单，每行每列藏着文档链接且分页）的难点不在「找链接」，
而在**上下文与命名**：

1. **行/列上下文** —— 每条链接都记录 `rowLabel`（行首单元格文本）、`colHeader`（列标题）、
   `text`（链接文字）、`pageIndex`（来自第几页）。模型据此能向用户说明"下载的是哪些"。
2. **文件命名** —— URL 里的文件名常常是 `download?id=123` 这种无意义值，
   所以用 `行标签_列标题.pdf` 命名；跨页重名再自动加 `_2` 后缀。
3. **翻页** —— 自动识别「下一页」控件（`rel=next`、`aria-label`、`class~=next`、
   文本「下一页/next/›/»」等），逐页点击并累积。

两个实测踩到的坑：

- **翻页检测必须用内容指纹，不能用「行数 + 文本长度」**。翻页后行数常常相同、
  文本长度也接近，用长度做指纹会误判「内容未变」而提前停止，只拿到第一页。
  现改用表头 + 前几行文本的内容哈希。
- **必须能回到第一页**。否则第二次调用只会拿到「当前页往后」的数据。
  现在采集前会先点「上一页」回首页。

末页判定也做了多路兜底：按钮 `disabled` / `aria-disabled` / 祖先 `li` 带 disabled 类 /
`pointer-events: none` / 点击后内容未变。

## 6. 模型服务商适配层

内部统一消息格式（接近 Anthropic 的多模态结构，天然支持图片与工具）：

```js
{ role: 'user', content: [ {type:'text', text}, {type:'image', mime, data} ] }
{ role: 'assistant', content: [ {type:'text'}, {type:'tool_use', id, name, input} ] }
{ role: 'user', content: [ {type:'tool_result', tool_use_id, content, is_error} ] }
```

各协议只在边界转换：

| 服务商 | 协议 | 工具格式 | 图片 |
|---|---|---|---|
| OpenAI 兼容（OpenAI/DeepSeek/Kimi/通义/智谱/硅基/OpenRouter/Ollama/LM Studio） | `/chat/completions` | `tools[]` + `tool_calls` | `image_url` |
| Anthropic | `/messages` | `tools[]` + `tool_use` | `image` source |
| Gemini | `:streamGenerateContent?alt=sse` | `functionDeclarations` | `inlineData` |

流式增量处理：OpenAI 的 `tool_calls` 需按 `index` 拼接 arguments；Anthropic 需按
`content_block_start` / `input_json_delta` 重组；Gemini 直接给出完整 `functionCall`。

## 7. 安全设计

| 面 | 措施 |
|---|---|
| API Key | 只存 `chrome.storage.local`，不上云、不同步；relay 模式下可留在本地 companion |
| 遥测 | 无。代码中不存在任何统计上报 |
| 远程代码 | 无。MV3 禁止，且本项目零 CDN 依赖 |
| 权限 | 仅申请必需项；`<all_urls>` 是「在任意站点工作」的必要代价 |
| 内容脚本隔离 | 运行在隔离世界，默认不与页面 JS 共享变量；`page.eval` 显式声明在 MAIN world 执行 |
| 危险操作 | 系统提示词要求：提交表单/批量下载前先 `page.highlight` 并向用户说明 |
| companion | 只监听 `127.0.0.1`；代理仅允许 http/https，拦截 `file://` 等本地协议读取 |
| 数据留存 | 对话只在内存，关闭面板即清空；设置可一键清除 |

## 8. 验证体系

| 脚本 | 覆盖 | 结果 |
|---|---|---|
| `scripts/check-project.mjs` | manifest 引用的文件是否存在；工具 schema 与 handler 是否双向一致；工具描述是否够详细 | 通过 |
| `scripts/verify-e2e.mjs` | 真实启动 Edge → 加载扩展 → 打开测试页 → 逐项断言工具行为与 DOM 副作用（含分页表格批量下载） | 51/51 通过 |
| `scripts/verify-mcp.mjs` | MCP 握手 → 工具发现 → 桥接连通 → 经 MCP 驱动真实浏览器 → 本地工具配置 → 真实 ffmpeg 合并 HLS → 代理转发 | 23/23 通过 |

验证方式不是「检查返回值」，而是**检查副作用**：广告位 `display` 是否真的变成 `none`、
背景色是否真的改变、下载是否真的落盘、DOCX 是否真的能被 `zipfile` 解析。
